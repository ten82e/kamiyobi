# kamiyobi

高性能計算・ネットワーク・システム・人工知能・セキュリティ・データベース・グラフィックス・HCI・理論の国際会議および穴場ワークショップ・ジャーナルについて、論文投稿の締切と開催日を収集・正規化する。
上流データの取得、候補探索、ビルド、公開は手元の CLI と GitHub Actions で行い、JSON / CSV / Markdown と静的サイトを生成する。
生成した静的サイトは GitHub Pages で公開できる。

公開先は https://ten82e.github.io/kamiyobi/ である。

## 直近の締切と開催

直近 180 日の締切と開催の表は [upcoming.md](https://ten82e.github.io/kamiyobi/upcoming.md) にある。
締切を持たず開催日だけがわかっている会議も、開催の行としてここに出る。
この README は手書きで、ビルドが書き換えることはない。

## 生成物

投稿判断に使う正規化データ全体は `data.json`、一覧画面用の現在・近日期間カタログは
`catalog.json`、推薦モード用の会議プロフィールは `recommendation-index.json`、締切だけを扱う表は
`data.csv`、品質監視用の健全性レポートは `health.json`、直近の締切と開催日は `upcoming.md` にある。`data.json` と `health.json` には、旧 slot の統合を許可する明示的な `identity_migrations` 契約も含まれる。静的サイトでは会議名・締切・公式サイトを
検索でき、推薦機能は必要時に推薦インデックスを取得して論文の PDF/TXT をブラウザ内で処理する。
推薦インデックスは締切データと同じ公開物として維持され、埋め込みを取得・検証できない場合も
サイト全体は公開され、語彙スコアのみの推薦に切り替わる。

`upcoming.md` の日付も公式表記どおりに書き、曜日を添える（`2026-08-17(月) 23:59 JST`）。JST 宣言の国内会議は `2026-08-17 23:59 JST`、公式が AoE のものだけ `… AoE`、
表記なしは `… UTC`、`PT` などそれ以外の表記は `… UTC（公式 PT）`（換算せず原文を添える）。

## サイトの読み方（締切一覧）

公開サイト https://ten82e.github.io/kamiyobi/ の締切一覧は、日本の研究者がそのまま動作計画に使える形にしている。

- 日時は **JST と曜日を主表示**（`2026-02-07(土) 20:59 JST`）。2 段目に公式ページの表記を出す
  （`公式 2026-02-06 23:59 AoE` / `公式 JST 締切` / `… UTC`）。
  AoE（UTC-12）は「世界のどこかでその日が終わるまで有効」という締め方で、日本では AoE の翌日まで提出できる。
  AoE を併記するのは公式が AoE 締切のものだけ。JST 宣言の国内会議に AoE は出さない。
- 分野は日本語名で示す（ネットワーク / 人工知能 / セキュリティ …）。検索欄には会議名だけでなく
  「ネットワーク」「国内」などの分野名・区分を打っても絞り込める。
- 開催地は国名と開催形式だけを日本語に寄せる（`Alicante, Spain / Online` → `Alicante, スペイン / オンライン`）。
  会場名や都市名は壊さないようそのままにし、原文は一列にホバーしたときと詳細の「原表記」で見られる。
  「韓国」「オンライン」といった語でも検索できる。
- 主題タグも日本語で引ける。「機械学習」（80 件）・「自然言語処理」（31 件）・「コンピュータビジョン」（43 件）・
  「穴場」（44 件）・「ストレージ」など、会議名にその語が無くても検索欄でヒットする。詳細（行を選ぶ）にも「主題」として日本語で出す。
- 「投稿先を探す」の画面を URL で共有すると、相手は同じ画面を**空の論文欄**で開きます。
  未発表の原稿がリンク・閲覧履歴に残るのを避けるため、URL に論文のタイトル・概要は入れません
  （画面にもその旨を書いています）。受け取った側には同じ情報を入力してください。
- 「投稿先を探す」の候補は件数欄に総数、画面には上位 20 件を出し、「さらに表示」で残りを
  見ます（上位分が打ち切りであることは件数欄にも書きます）。
- 行の詳細の「今後の会期」と、0 件のときに出す次回会期の案内の開催地を、表と同じ書き方に
  直しました（変更前は「開催地: Kyoto, 日本」と並びに「＠Kyoto, Japan」が出ていました）。
- 同じ問題を、チェック欄とモードにも広げました。`?past=true` はチェックが入らず、画面にも
  何も出ない状態でした（`1` しか読まない実装だった）。これらは `1` / `true` / `0` / `false` を
  読み、読めない値なら「リンクのオンライン参加可のみ「maybe」はこの一覧で使えない値なので、
  チェックは入りませんでした」と出します。モードも読めない値のときは「締切の一覧を開きました」
  と実際に何を開いたかを書きます。
- 共有リンクの中にこの一覧が受け付けられない値（例: `?rank=B++`、未知の分野の鍵）が
  入っていたとき、**条件を黙って変えていました**。送った人は自分が見ていた画面を信じて
  共有するので、受け取った人が「思っていたより広い一覧」を開いているのに気づけません。
  これからは件数のうしろに「リンクのランク「B++」はこの一覧で使えない値なので、ランクの
  絞り込みは外れています」と、もらった値とどうしたかを出します。てびきに「画面を共有する」
  の項も足しました。
- 「投稿先を探す」の論文を選ぶ欄で、Word などの読めない形式を PDF のせいにしないようにしました。
  これまで `.docx` を渡すと pdf.js が失敗し、画面は「PDF から文字を読み取れませんでした
  （文字が入っていない PDF や、パスワード付きは読めません）」と言っていたので、自分の PDF の
  文字化けを疑って直せない方向へ探していました。いまは拡張子を実名で出して「対応しているのは
  PDF と TXT です」と伝え、TXT に保存し直すか下の欄へ貼る案内を出します（欄の注記にも同じことを
  書きました）。
- 行の文字をドラッグして選んだときは、行の詳細が開かないようにしました。会議名・会場・公式
  ページの名前をコピーしようとして選び離すと、選んだ物が詳細の欄と背景に隠れて消えていました
  （実測: 修正前は選択の有無とかかわりにドロワーが開いていた）。他の場所に残った選択を理由に、
  いま押した行まで開かなくなることはしません。
- 「画面を共有する」に、開いていた行の詳細も入るようにしました（`?row=`）。これまで共有できた
  のは絞り込み・並び順・てびきの開閉だけで、「この締切を見て」と送ったのに、受け取った側は
  表のなかから同じ行を探す必要がありました。リンクを開くと、送った人が選んでいた行が選択行に
  なり、行の詳細も開いた状態になります。条件も一緒に来るので通常は同じ行が見つかりますが、
  データの生成日が違えば見つからないことがあります（そのときは表だけを出します）。
- 「投稿先を探す」画面で印刷したときの但し書きを直しました。これまで締切一覧用の文をそのまま
  書いていたため、候補のカードが並んだ紙に「表示 0 件」と刷れていました。印刷物はあとで単体で
  回覧されるので、これは紙のうえで噓です。いまは「投稿先を探す画面 ／ 候補 N 件」と実際の内容を
  書き、候補のカードにも公式ページのアドレスを併記するようにしました（紙では URL を押せない
  ため、表と同じ扱いにしています）。
- 種別欄の下に小さく添える収録元の締切名に、「原表記:」と書くようにしました。既定画面の行は
  すべてこの名前を持っていて（最も多いのは「Submission deadline」の 129 行）、印も無く並ぶため
  画面の種別（概要締切・論文締切）と並ぶ別の分類のように見えていました。会期の項で既に使って
  いる語に揃え、てびきにも「収録元の呼び方その物で、この語でも検索が引ける」と書きました
  （実測: 「Submission deadline」で 267 行、「発表申込締切」で 19 行）。
- キー操作の案内は「画面の幅」ではなく「操作手段」で出すようにしました。これまで 640px 未満の
  幅で件数欄のショートカット注記とてびきのキーボードの項を消していましたが、`j` / `k` / `d` /
  `/` は幅とかかわりに効くので、パソコンの窓を分割して狭くした人だけ「動くのに案内が無い」
  画面になっていました。タッチでしか操作できない端末でだけ隠します。
- 件数の数え方を画面で揃えました。件数欄は「全 3235 件」、てびきは「全 3,235 件」と、
  同じ数が二つの形で見えていました。4 桁目から 3 桁ごとに区切るようにし（環境差のある
  `toLocaleString` は使わない）、画面の「… 件」を出す 25 箇所をすべて同じ関数経由にしました。
  素の数値が混ざっていないかをビルド成果物から洗う検査も足しています。
- 画面に出る文に折り返し形式の指定（markdown の記号）がそのまま残っていた箇所を直しました。
  てびきの本文の 3 か所に `` ` `` が現れ、「評価なし」の吹き出しにも記号と画面に無い語
  （内部表記）が出ていました。てびきは `<code>` に統一し、吹き出しは「評価が付いていない
  こと」と「 kamiyobi が公式で裏を取れていないこと（未確認）」は別に出す、という区別の
  書き方にしました。検査もバッククォートまで見るように増やしています。
- 投稿先を探すモードのカードだけが「受付状況不明」という、ほかの画面でもてびきにも無い語を
  出していました。画面の「分からない」は未確認 / 該当なし / 評価なしの三語に揃えてあるので、
  「受付状況未確認」に直し、受け付け中で次回の日付だけが出ていない行は
  「次回締切の日付が未確認」と、分からない部分だけを書くようにしました。
- 0 件のとき、支援技術には「条件を緩めると出ます」とだけ読めていました。画面の下には
  「外せる条件」を書いてあるのにその存在を言わず、逆に外せる条件が残っていない画面でも
  「緩めると出ます」と言っていました。外せる条件が残いている画面では「下に外せる条件も
  書いてあります」と言い、残っていない画面ではその事実を言うようにしました。
- 「見方のてびき」は畳んだまま開くため、閉じた中はブラウザのページ内検索（Ctrl+F）にかかりません。
  てびきを開いた状態をそのまま引き継ぐ `?help=1` を足したので、教える側が開いた状態でURL を
  コピーすれば、受け取った人の画面でも開いています。てびきの見出しも、専門語を並べたものから
  画面に出る語（「推定」「未確認」「該当なし」など）を並べたものに変えました。
- 投稿先を探すモードで、行の内訳に「分野の一致 +18」のような数字が並んでいました。同じカードの
  「一致スコア 65点」と足し合わせると合わず（実測: 内訳の合計 27 / スコア 65）、別々の計算で
  作った単位違いの数字を並べていました。内訳は**当たった要素の名前だけ**を出し、スコアは内訳の
  合計ではないことをてびきに書きました。あわせて、画面に出る文へ markdown の `**強調**` が
  混じっていた行を直し、表示される本文に `**` が残らない検査を足しました。
- 投稿先を探すモードの各カードに「情報不足」という語がほぼ全行に出ていました（実測: 概要・
  キーワードまで書いた入力で表示 25 件のうち 23 件）。自分の論文の書き方が悪いのだと
  誤解させる語だったので、実際の判定内容に合わせて「重なりうすい」に変え、てびきに
  「候補」「重なりうすい」の意味と、語彙検索だけではほとんどが後者になることを書きました。
- 列をまたぐ行（月見出し・過ぎた締切の見出し・行の詳細）の列数を 3 箇所に直書きしていました
  （実測で `colSpan = 7` が 3 件）。同じ数は表の見出し 7 列・行のラベル 7 個にも出ていたので、
  1 箇所にまとめて、見出しの列数と行のラベル数と突き合わせる検査にしました。
- 「条件をまとめて外す」が出る条件の数え上げに、推定が入っていませんでした（0 件の案内は
  推定を「外せる条件」に並べるので、数え上げがズレると「案内は外せるというのにボタンが
  出ない」が起きます）。今日は収録の都合で踏めないため、目に見える不具合ではなく先行する
  直しです。
- 0 件の画面の案内が、条件の名前だけ並べて数字を書きませんでした。同じ画面の件数欄は
  「推定 134 件」「過去の締切 2,317 件」のように内訳を出しているのに、案内の側には数字が
  無く、6 項目のどれから外す価値があるか読めません。案内の各項目にも同じ数字を添えるように
  しました（例: 「過去の締切も表示」をオン（過去の締切 2317 件））。**行を 1 も隠していない
  条件は勧めない**ようにしたので、外し直しの手間は増えません。
- 画面をクリックするたびに快捷键が死んでいたのを直しました。条件のチェックや並び替えの
  ボタンを押した直後は、`/` で検索欄に飛べず `j` も行を動かしませんでした（ボタンに
  フォーカスが乗っているとすべてのキーを止める作りだった）。ボタンが本当に受け取る
  `Enter` と `Space` だけがボタンに残り、他はショートカットに渡ります。論文の本文を打つ欄で
  `/` が消えることは引き続きありません（完成した画面の処理系を実際に叩いて確かめています）。
- 前項で CSV に書いた語を、画面の検索欄で打つと 0 件になる状態を直しました（検索語を作る
  場所が「該当なし」を知らず、常時受付の行は `会期該当なし`・`ランク未確認` で引けなかった）。
  検索語も同じ所から作るように一本化し、実測で 800 行すべて「CSV に書いた語がその行で引ける」
  ことを検査にしました（`会期該当なし` 22 件、`会期未確認` 264 件、`ランク未確認` 締切 450 件
  ＋常時受付 22 件。締切行が「該当なし」で引けない＝混ざらないことも確かめています）。
- CSV に書き出すと、画面の「未確認」「該当なし」が消えていました（値の列が空になるだけで、
  状態の列は推定・延長などしか持たなかった）。表計算に持ち出した人が「収録が無いのか、まだ
  確認できていないのか」を区別できなかったため、**状態の列**に `会期未確認・開催地未確認` のように
  画面と同じ語で書き出すようにしました（列は増やしていません。値の列は空のままなので、
  値で並べ替えてから状態を読めます）。常時受付の行は `会期該当なし` として出て、確認待ちの行と
  混ざりません。実測で、会期が未知の 264 件すべてが `会期未確認` を持ち、常時受付 22 件は
  すべて `会期該当なし`（`会期未確認` は 0 件）です。
- `upcoming.md` の列の見出しに **`R`** という一文字があり、何が何だか分かりませんでした
  （値は `R1`・`R2`・`-`）。一覧と同じ **`ラウンド`** に変え、表の上に列の凡例を足しました
  （「残り」の数え方、種別「開催」は締切ではなく会期そのものであること、「推定」の意味）。
  この表は条件欄もてびきもない単体のファイルとして読まれるので、表のうえだけで意味が
  取れるようにしています。
- 常時受付のジャーナルの会期・開催地を「未確認」と出していました。ジャーナルには会期も会場も
  そもそも無いので、これらの行は「**該当なし**」を出すようにしました（「未確認」は kamiyobi が
  公式で裏を取れていない場合だけの語です）。「該当なし」で検索すると、その行だけが出ます。
- データが古くなっていることに、画面が気づきませんでした。更新は日次の運用なので、生成から
  **3 日以上**経った一覧を開いた人には「データは N 日前に生成されたものです（更新が止まっている
  可能性があります）」を出すようにしました。締切のサイトで古い一覧を最新と誤り、投稿の機会を
  逃すのがいちばん悪い失敗です。時計のズレや生成時刻が読めない値では出しません（根拠の無い
  警告を出さない）。
- 印刷物に**並び順**が残っていませんでした（条件・件数・日時だけ）。会期順やランク順に並べ替えて
  配ると「紙のうえで何の順か」が分からなくなるので、条件のうしろに並び順も書くようにしました
  （列の名前は画面の見出しから取り、目印の矢印は落とし、既定の並びでも残します）。
  てびきのキーボードの項で、`/` と `Esc` の説明が二回書かれていたのも直しました。
- 表に出している**会期**の列が並べ替えできませんでした（押せたのは残り・日時・会議・ランクの
  4 列だけ）。出張の計画は「いつ開かれるか」順で見ることが多く、既定画面 478 行を締切順のまま
  会期順に数えると 707 箇所の逆転がありました。会期でも並べ替えできます（会期が未確認の行は
  向きに関係なく末尾。会期順のときは締切月の見出しを出しません）。
- 論文から投稿先を探すとき、件数の欄に出る「意味検索は利用不可（語彙検索のみ・原因: …）」の
  理由が `embeddings unavailable` などの英語でした（2026-09-23 実測）。画面は
  「意味検索のデータが読み込めませんでした」などの日本語に直し、詳しい符号はこのページの
  要素に属性で残るようにしました（調査用に捨てない）。てびきにも「意味検索が使えないとき」の
  項を足しました – 候補も一覧もそのまま使えます。
- 締切のデータが入っていない状態でページが開かれたとき、「条件を緩めると出ます」と
  的外れな案内を出していました（緩めても増えないので）。その場合はデータが入っていないこと
  を先に言うようにしました。同じ状態でヘッダーの「データ生成」が空欄・`undefined`・

## サイトの使い方（投稿先レコメンド）

公開サイト https://ten82e.github.io/kamiyobi/ の上部で、**読んだ論文（似た論文）または投稿予定の論文の PDF / TXT を選ぶだけ**で、合いそうな会議・ジャーナルを適合度順にランク付けする（複数ファイル可）。

- PDF は固定版 pdf.js で先頭 3 ページのタイトル・概要・キーワードを読み取って照合する（未接続環境では TXT のみ対応）。ページには許可済み CDN とモデル接続だけを記した CSP を設定している。
- 内部では 1 ファイルを `タイトル | 本文` の 1 行として処理する。掲載先タグ（`| RTSS` 等）による「掲載先一致」優先は手動の行入力時のみの機能だが、サイト上はアップロードが主経路のため通常は不要。
- 分野チップが空のときは論文内容から分野を自動判定して表示する（手動でチップを選ぶとその分野に絞る）。
- 英語・日本語どちらのタイトル/キーワードにも対応。日本語の場合は会議名の日本語表記と部分一致し、国内研究会（情報処理学会・電子情報通信学会等）も拾う。
- **AI による意味検索の補助**: 会議スコープはビルド時に all-MiniLM-L6-v2 で埋め込み済み（`embeddings.json`）。ブラウザで transformers.js が使える環境では、論文入力との意味類似度を計算し、入力言語と内容語数に応じた重みで語彙スコアと合成する。CDN が使えない環境では語彙検索のみで動作する。
- 埋め込みが未提供・不正・古い場合は、画面に意味検索が利用できず、語彙検索のみ有効であることを表示する。締切一覧はこの状態でも利用できる。
- AI 補助の実行時処理とモデル取得は固定 URL の外部接続を使う。接続できない場合も語彙検索と TXT 入力は継続する。
- 適合度の内訳は、会議名・分野・主題タグとの言葉の一致と掲載先タグの合算（画面表示は
  「分野の一致」「主題の一致」などの言い方にしている）。スコアリングの正本は `site/recommender.ts` で、ビルド時に `recommender.js` を生成する。`tests/recommender.test.ts` が実データで回帰検証する。

## 穴場の会議・ジャーナルの探索

上流に登録されていない特化ワークショップ、地域シンポジウム、ジャーナルの Call for Papers などの「穴場」を自律探索するには以下を実行する。

```sh
node src/cli.ts discover --dry-run
```

候補レジストリを永続化する場合:

```sh
node src/cli.ts discover --candidate-out data/discovered_candidates.yaml
```

`--out` は明示的に `extra.yaml` 互換の一時出力を作る場合だけ使う。
旧互換出力を追記する `--append` は、候補レジストリの更新には使わない。
候補レジストリはこのコマンドで更新する。`data/discovered_candidates.yaml` に既存レコードを
マージし、レビュー済みの状態・メモ・初回発見時刻は維持する。再発見時は最終発見時刻と
証拠だけが更新される。
運用上の確認対象は `data/discovery/active.yaml` であり、期限切れ・重複・対象外などの候補は
`data/discovery/archive.json` に理由付きで移す。
候補は公式サイトで裏取りするまで `manual.yaml` または `curated.generated.yaml` には昇格しない。
探索対象を分野や年で絞るには `--categories`（例: `hpc,systems`）と
`--min-year`（省略時は実行時の UTC 年）を使う。

溜まった候補を締切昇順・重複・ハゲタカ会議の疑い付きで一覧するには `review` を使う。

```sh
node src/cli.ts review
```

`--limit` で表示件数を絞り、`--candidates` で候補 YAML の場所を変えられる。
候補の昇格（下記）の前に、ここで重複や怪しい候補を確認する。

**候補の昇格手順**（収録の裏取り原則: 締切は公式サイトで HTTP 確認できたもののみ）:

1. `data/discovery/active.yaml` から気になる候補を選ぶ
2. `scripts/observe-cfp.ts --url <公式URL> --body <保存先>` で公式ページの応答と本文を保存する。`--body` は必須
3. 観測 JSON に会議・カテゴリのレビュー結果を付け、`scripts/verify-cfp.ts` で本文 hash、公式ドメイン、抽出値、取得版を検証する
4. `scripts/promote-candidates.ts` で本文を同梱した manifest 付き batch を生成し、`npm run generate:curated` で生成された正典を確認する
5. ビルドして収録されることを確認する

公式ページの再確認は、公開済み `data.json` の次回確認時刻を過ぎた締切だけを対象にする。
本文は SHA-256 付きで `data/evidence/blobs/` に保存し、日付の変更は台帳へ記録する。
公開データを自動上書きしないため、変更後の値は台帳の resolution を確認してから反映する。

```sh
node src/cli.ts reverify --due --now 2026-08-31T00:00:00Z
```

証拠本文の参照整合を検査し、未参照本文を回収する。

```sh
node src/cli.ts evidence verify
node src/cli.ts evidence gc --dry-run
```

上流の取得結果は `data/source-snapshots/` に源ごとに保存する。
一次ソースの退避は `data/source-snapshots/primary.json` を使い、オフラインビルドでも検証済み観測を復元できる。

## 更新の仕組み

手元では次の順で更新する。push 後は `.github/workflows/ci.yml` が同じ検査を実行し、
main では `deploy.yml` が Pages を配信する。

```sh
# 1. 上流を取得して正規化し、一次ソース観測を適用する
node src/fetch-primary.ts --apply
# 1b. 国内研究会の会期・締切を研究会別スケジュール表から更新する（既定は dry-run）
node scripts/refresh-ieice.ts --cache-dir .cache/ieice
#     新しい研究会を足すときは data/manual.yaml へ editions: [] のブロックを置いてから
#     実行する（研究会名は公式ページのタイトルから取る。dry-run で追加予定が出るはず）
#     情報処理学会の研究会も同じスケジュール表に乗っているので、ipsj.or.jp が 403 でも
#     IPSJ の研究会（HPC・CSEC・ARC・EMB・SE・DPS・UBI・DBS・AL・IFAT・CGVI・IOT）は
#     ここで更新できる
node scripts/refresh-ieice.ts --cache-dir .cache/ieice --apply
# 2. 候補探索（新規会議の発見）
node src/cli.ts discover
# 3. promotion batch から local 正典を生成
npm run generate:curated
# 4. フルビルド（public/ を生成）
node src/cli.ts build --out public
# 5. 意味検査と health gate
npm run update
```

全上流が fresh の場合だけ `data/snapshot.json` を更新する。このスナップショットは上流が
落ちたときの退避先を兼ねており、取得に失敗した日は前回の内容から生成を続ける。
スナップショットでも補えないほど収集が縮退した場合は、ビルドが非ゼロで終了して公開物を作らない。

変更は `git branch` → ローカルで `npm run typecheck && npm run check && npm test` → `git merge` の順で main に反映する。

## 収録範囲を変える

`config.yaml` を編集する。

分野の割り当ては `taxonomy` にある。
上流の分野を丸ごと取り込む `ccfddl_subs` と、会議名を並べる `venues` の組み合わせで決めている。
個別許可リストにすると上流に新しく追加された会議が永久に出てこないため、この方式を採っている。
`venues` に書いた会議はランク判定を迂回して必ず残る（名指しは収録の意思表示でもある）。
特定の会議を外したいときは、その分野の `exclude` に会議のキーを足す。

```yaml
taxonomy:
  networking: {ccfddl_subs: [NW]}
  hpc:        {venues: [sc, ipdps, hpdc, icpp, cluster]}
```

ランクによる絞り込みは `rank_filter` にある。
空にすれば無条件で通る。
`keep_if_no_rank` を真にしておくと、ランク情報を持たない会議（local 正典由来のものなど）が落ちない。

```yaml
rank_filter:
  ccf: [A, B]
  core: ['A*', A, B]
  keep_if_no_rank: true
```

上流に無い会議を手入力で足したいときは `data/manual.yaml` に書く。
上流の記述が誤っているときは `data/overrides.yaml` で訂正するか、除外する。
どちらも編集後は手元でビルドし直して結果を確かめる。

## 既知の限界

締切情報は上流データに依存しており、正確性を保証しない。
投稿の前に必ず各会議の公式サイトで確認すること。

推定締切は前年の同種の締切から機械的に作ったものである。`data.json` と `data.csv` に含めるが、
`estimated` フラグで確定値と区別している。サイト上でも推定であることを明示している。
根拠のない締切を確定値として扱わない方針を採っている。

締切を持たず開催日だけがわかっている会議（ISC High Performance・HOTI・P4 Workshop・Linux Plumbers Conference・情報処理学会 HPC 研究会など）は、種別「開催」の項目としてサイトと `upcoming.md` に出る。
開催の行は会期の最終日を過ぎるまで既定の表示に残る。
締切も開催日も裏が取れていない会議は、どこにも出さない（手入力ファイルには未確認である旨のコメントだけを残せる）。
国内の研究会・シンポジウム（`tags: [domestic-jp]`）は通しやすい発表枠として local 源で維持している。サイトの「国内研究会・国内シンポジウムのみ」で絞れる（`?domestic=1`）。
電子情報通信学会の研究会は[研究会発表申込システムの開催スケジュール表](https://ken.ieice.org/ken/program/)を裏取り元にする。この表は「発表申込締切日」を**日付だけで**示すため、締切は `date-only`（サイトでは「時刻未確認」）で収録する。時刻を補完しない。次の回の締切が未公開の会は会期だけ収録し、締切欄は空のままにする。

会期は上流では自由文で書かれており、解釈できない書き方のものは開催イベントを作れない。
日付だけが確認でき、時刻とタイムゾーンが不明な締切は `date-only` として収録する。
この値は UTC、JST、AoE の公式時刻へ変換しない。
サイトは UTC+14 の日付開始から UTC-12 の日付終了までを不確実性区間とし、区間内では終了済みの可能性を表示する。
上流の誤りはそのまま反映されるので、気づいたときは `data/overrides.yaml` で訂正する。

上流のスキーマが変わればビルドが壊れうる。
その場合も前回のスナップショットから生成が続くため、サイトが即座に空になることはないが、データは古いままになる。
